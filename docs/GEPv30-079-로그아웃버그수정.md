## 1. 작업 목적
로그아웃 후 새로고침 시 Supabase가 서버 세션을 복원해 자동으로 재로그인되던 버그를 수정. `signOut()`에 `scope: 'global'`을 지정하지 않아 서버 세션이 삭제되지 않았고, 메모리 상태(`authStore`)도 리다이렉트 직전까지 `authenticated`로 유지되고 있었음.

## 3. 주요 변경사항

### 변경 전
```javascript
const handleLogout = async () => {
  try {
    await supabase.auth.signOut()
  } catch (e) {
    console.warn('[GEP] signOut exception:', e)
  }
  try {
    Object.keys(localStorage)
      .filter(k => k.startsWith('sb-') || k === 'gep_auth_v1')
      .forEach(k => localStorage.removeItem(k))
  } catch {}
  window.location.href = '/'
}
```

### 변경 후
```javascript
const handleLogout = async () => {
  // Step 1: 메모리 상태 즉시 guest로 전환 (UI 반응)
  useAuthStore.getState().clearAuth()

  // Step 2: Supabase 서버 + 모든 기기 세션 삭제
  try {
    await supabase.auth.signOut({ scope: 'global' })
  } catch (e) {
    console.warn('[GEP] signOut exception:', e)
  }

  // Step 3: 모든 GEP / Supabase localStorage 키 강제 삭제
  try {
    const keysToDelete = Object.keys(localStorage).filter(
      k => k.startsWith('sb-') || k.startsWith('gep') || k.startsWith('gep:')
    )
    keysToDelete.forEach(k => localStorage.removeItem(k))
  } catch {}

  window.location.href = '/'
}
```

**핵심 차이:**
- `scope: 'global'` 추가 — 누락 시 서버 세션이 살아있어 새로고침 후 Supabase가 세션을 복원
- `clearAuth()`를 signOut 이전에 선행 호출 — 리다이렉트 전까지 메모리 상태가 `authenticated`로 남아있던 문제 해소
- localStorage 삭제 필터를 `gep_auth_v1` 단일 키에서 `gep`/`gep:` 접두 전체로 확장 — `examStore`(`gep:v1:examStore:*`) 등 다른 GEP 키도 함께 정리
