## 2. 참고 화면에서 추론되는 디자인 세트

### 2.1 전체 인상

참고 화면은 일반적인 흰색 업무형 UI가 아니라, 프레젠테이션형 교육 콘텐츠에 가까운 어두운 고대비 디자인이다. 핵심 키워드는 다음과 같다.

- 다크 네이비 배경
- 고채도 포인트 컬러
- 큰 제목과 짧은 문장
- 카드형 정보 블록
- 막대그래프·타임라인·강조 숫자
- 화면 상단 또는 카드 상단의 얇은 컬러 라인
- 학습자가 내용을 즉시 스캔할 수 있는 강한 위계

### 2.2 색상 체계

추론되는 기본 팔레트:

| 용도 | 색상 성격 | 예시 |
|---|---|---|
| 전체 배경 | 거의 검정에 가까운 딥 네이비 | `#080B14`, `#0B1220` |
| 카드 배경 | 배경보다 한 단계 밝은 블루그레이/퍼플블랙 | `#171827`, `#202033`, `#1E293B` |
| 본문 텍스트 | 밝은 회색 | `#CBD5E1`, `#A5ADBA` |
| 제목 텍스트 | 순백 또는 근백색 | `#F8FAFC` |
| 메인 포인트 | 전기 블루·시안 | `#2F6BFF`, `#22D3EE` |
| 보조 포인트 | 퍼플 | `#8B5CF6` |
| 경고·강조 | 오렌지·앰버 | `#F59E0B`, `#FFB020` |
| 정답·완료 | 민트·그린 | `#34D399` |
| 위험·오답 | 코랄·레드 | `#FB7185` |

### 2.3 타이포그래피

참고 화면은 텍스트가 기능 설명보다 시각적 메시지 전달에 집중되어 있다.

- 제목: 굵고 큰 산세리프
- 보조 문장: 회색, 중간 크기, 짧은 줄
- 숫자: 매우 크게 표시
- 키워드: 블루·오렌지·퍼플 등 포인트 컬러로 분리
- 자간은 넓게 쓰는 경우가 있으나 앱 UI에서는 과도한 자간 확대는 피하는 것이 좋다.

GEP에는 `Pretendard`, `SUIT`, `Noto Sans KR` 계열이 적합하다. 현재 앱은 system font 기반이므로 디자인 세트를 명확히 하려면 폰트 기준도 정해야 한다.

### 2.4 레이아웃 패턴

참고 화면에서 반복되는 패턴:

- 2열 비교 카드
- 3개 핵심 지표 카드
- 타임라인형 목록
- 카드 내부 왼쪽 아이콘 + 오른쪽 설명
- 긴 설명보다 짧은 라벨과 큰 수치
- 얇은 진행 바 또는 상태 바
- 배경과 카드의 명도 차이를 크게 두되, 카드 그림자는 약하게 사용

## 3. 현재 GEP v3.0 UI와의 차이

현재 앱은 Tailwind 유틸리티 클래스를 각 화면에 직접 적용하는 구조다.

확인한 대표 파일:

- `src/index.css`
- `src/App.css`
- `src/pages/Home.jsx`
- `src/components/AppHeader.jsx`
- `src/pages/Question.jsx`
- `src/pages/ServiceAHome.jsx`
- `src/pages/ServiceBHome.jsx`
- `src/pages/StatsDashboard.jsx`

현재 디자인 특성:

- 밝은 배경 `#f3f4f6`, 흰색 카드 중심
- 파스텔 계열 메뉴 카드
- `rounded-2xl` 카드가 많음
- `bg-blue-50`, `bg-green-50`, `bg-violet-50` 등 Tailwind 색상이 직접 박혀 있음
- 페이지별 스타일 편차가 있음
- 디자인 토큰이나 공용 카드/버튼 컴포넌트가 충분히 분리되어 있지 않음

따라서 참고 디자인으로 바꾸려면 단순 색상 교체보다 먼저 디자인 토큰과 공용 컴포넌트 정리가 필요하다.

## 4. GEP에 적용할 수 있는 방향

### 4.1 직접 복제는 부적절

참고 화면은 강의 슬라이드용 디자인이다. GEP는 장시간 문제풀이 앱이므로 그대로 복제하면 다음 문제가 생길 수 있다.

- 긴 문제 지문 가독성 저하
- 모바일 작은 화면에서 과도한 장식
- 색상 대비가 강해 피로도 증가
- 학습 통계와 문제풀이 버튼의 기능성이 약해질 위험

따라서 "슬라이드 디자인 복제"가 아니라 "고대비 학습 대시보드형 디자인 세트로 재해석"하는 것이 맞다.

### 4.2 제안 디자인 세트

작업명:

`GEP Focus Dark Design Set`

목표:

- 시험 대비 긴장감
- 현재 위치를 즉시 자각하게 하는 대시보드
- 반복 오답과 취약 과목을 강하게 드러내는 시각 위계
- 문제풀이 화면은 장식보다 가독성 우선

핵심 톤:

- 배경: 딥 네이비
- 카드: 어두운 블루그레이
- 기본 텍스트: 밝은 회색
- 핵심 수치: 흰색 또는 오렌지
- 과목 색상:
  - 법령: 시안/블루
  - 손보1부: 민트/그린
  - 손보2부: 퍼플
  - 반복 오답/위험: 코랄/레드
  - 시험일/D-Day: 앰버/오렌지

## 5. 권장 UI 구성

### 5.1 홈 화면

현재 홈은 기능 메뉴가 많아 정보가 흩어져 보인다. 참고 디자인을 적용한다면 다음 구조가 적합하다.

1. 상단: 사용자명, D-Day, 설정/로그아웃
2. 첫 카드: "오늘의 학습 위치"
   - 오늘 푼 문제
   - 오늘 정답률
   - 누적 풀이
3. 두 번째 카드: 과목별 상태
   - 법령/손보1부/손보2부 진행 바
   - 반복 오답 위험 배지
4. 학습 메뉴: 서비스 A/B/OX/모의고사/통합오답을 고대비 카드로 정리
5. 하단: 가장 급한 학습 행동 1개를 CTA로 제시

### 5.2 문제풀이 화면

문제풀이 화면은 다크 테마 적용 시 가장 조심해야 한다.

권장:

- 문제 본문 영역은 완전 검정이 아니라 어두운 카드 위 밝은 텍스트
- 선택지는 4개 버튼을 동일 크기로 고정
- 정답/오답 후 색상은 강하게
- 해설 또는 정답 피드백은 하단 시트형 카드
- 진행률은 상단 얇은 바

비권장:

- 문제 본문에 과도한 네온 효과
- 긴 지문에 낮은 대비 회색 텍스트
- 모든 버튼에 강한 그림자/글로우

### 5.3 통계 화면

참고 디자인과 가장 잘 맞는 영역이다.

권장:

- 큰 숫자 카드
- 반복 오답 Top N 카드
- 과목별 가로 막대
- 2회 이상/3회 이상/4회 이상 틀린 문제 비율 시각화
- 위험 과목은 오렌지/레드 계열로 즉시 표시

## 6. 구현 방식

디자인 변경은 단계적으로 진행해야 한다.

### Step 1. 디자인 토큰 도입

`src/index.css` 또는 별도 CSS 파일에 다음 토큰을 정의한다.

- 배경색
- 카드색
- 텍스트색
- 과목별 색
- 위험/경고/성공 색
- radius
- shadow
- spacing

이 단계에서는 화면을 바꾸지 않고 토큰만 준비한다.

### Step 2. 공용 컴포넌트 생성

다음 공용 컴포넌트를 만들면 전체 UI를 안정적으로 바꿀 수 있다.

- `AppShell`
- `AppHeader`
- `MetricCard`
- `StudyCard`
- `SubjectProgress`
- `PrimaryActionButton`
- `StatusBadge`

### Step 3. 홈 화면 파일럿 적용

전체 앱을 한 번에 바꾸지 말고 홈 화면만 먼저 적용한다.

대상:

- `src/pages/Home.jsx`
- `src/components/AppHeader.jsx`

검증:

- 모바일 390px
- 태블릿 768px
- 데스크톱 1280px
- 로그인 전/후
- 관리자/일반 사용자
- 잠금 서비스 표시

### Step 4. 문제풀이 화면 적용

대상:

- `src/pages/Question.jsx`
- `src/components/QuestionView.jsx`
- `src/components/AnswerButton.jsx`

검증:

- 긴 지문
- 보기 4개 길이 차이
- 정답/오답 상태
- 하단 버튼 고정
- 모바일 세로 스크롤

### Step 5. 통계·오답 화면 적용

대상:

- `src/pages/StatsDashboard.jsx`
- `src/pages/WrongReview.jsx`
- `src/pages/UnifiedWrongReview.jsx`
- `src/components/stats/*`
- `src/components/wrong/*`

이 단계에서 참고 디자인의 카드, 막대그래프, 강한 숫자 위계를 본격 적용한다.

## 7. 예상 리스크

| 리스크 | 내용 | 대응 |
|---|---|---|
| 가독성 저하 | 다크 배경에서 긴 문제 지문 피로도 증가 | 문제 본문 전용 대비 기준 설정 |
| 변경 범위 확대 | Tailwind 클래스가 화면별로 직접 박혀 있어 일괄 교체 어려움 | 토큰과 공용 컴포넌트 먼저 도입 |
| 모바일 깨짐 | 큰 제목과 큰 숫자가 작은 화면에서 넘칠 수 있음 | 고정 폭·줄바꿈·텍스트 축소 규칙 필요 |
| 기존 기능 회귀 | 홈/문제/통계에 인증·카운팅 조건이 섞여 있음 | 디자인 변경 시 로직 변경 금지 원칙 |
| 색상 의미 혼동 | 현재 과목별 색과 정답/오답 색이 섞여 있음 | 색상 의미표를 먼저 확정 |

## 8. 권장 승인안

디자인 변경을 승인한다면 다음 범위로 승인하는 것이 좋다.

### 승인 범위

- 디자인 세트 정의
- CSS 변수/토큰 추가
- 공용 UI 컴포넌트 도입
- 홈 화면 1차 시안 구현
- 문제풀이 화면은 아직 전면 변경하지 않고 검토용 시안까지만 진행

### 금지 범위

- 문제 데이터 수정
- 카운팅 로직 수정
- Supabase 스키마 수정
- 인증/승인 로직 수정
- 서비스 메뉴 구조 변경
- 통계 산식 변경

### 완료 조건

- 홈 화면이 새 디자인 세트로 정상 표시
- 기존 기능 메뉴가 모두 유지
- 로그인 전/후 상태가 깨지지 않음
- 모바일과 데스크톱에서 텍스트 겹침 없음
- `npm run build` 성공
- 변경 전후 스크린샷 비교 보고

## 9. 결론

참고 디자인은 GEP v3.0의 학습 통계 중심 가치와 잘 맞는다. 특히 큰 숫자, 고대비 카드, 과목별 진행 바, 반복 오답 강조는 GEP의 차별성인 "현재 위치 자각"을 강화할 수 있다.

다만 그대로 복제하면 강의 슬라이드 같은 화면이 되어 실제 문제풀이 앱의 가독성과 사용성이 떨어질 수 있다. 따라서 `GEP Focus Dark Design Set`으로 재해석하고, 먼저 홈 화면과 통계 화면에 제한적으로 적용한 뒤 문제풀이 화면은 별도 가독성 검증을 거쳐 확장하는 것이 적절하다.

추천 다음 단계는 `GEPv30-134` 개발지시서로 "디자인 토큰 및 홈 화면 시안 1단계"를 정의하는 것이다. 조대표님 승인 전까지 코드와 디자인은 변경하지 않는다.
