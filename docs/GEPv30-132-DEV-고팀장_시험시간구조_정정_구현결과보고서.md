## 1. 배경 — 사전 조사에서 확인된 사실 (코드 직접 검증)

조대표 지시 직전, 전달받은 "노팀장"·"선과장" 의견은 현재 코드 상태를 "1부 90분+2부 90분(180분, 60+60문항)"으로 전제하고 대규모 재설계를 제안했으나, `mockExamConfig.js`·`customMockConfig.js`·`exams.json`을 직접 읽어 검증한 결과 **이 전제 자체가 사실과 달랐다.**

| 항목 | 전달받은 전제 | 실제 코드 (검증됨) |
|---|---|---|
| 시간 구조 | 90분+90분(180분) | 법령 40분 + 손보 80분 = 120분 |
| 문항 구성 | 60+60문항 | 법령40+손보1부40+손보2부40 = 이미 정확 |
| 세부과목 배치 | 해상보험→1부 오배치 | 해상보험은 이미 손보2부(정상), 근재·기술보험 카테고리는 코드에 존재하지 않음 |

→ **결론: 대규모 재설계 불필요. 실제 갭은 시간 값 3개(공고 기준 미반영)뿐.** 세부과목 재분류는 실사용 데이터상 문제가 없어 조대표 승인으로 철회됨.

## 2. 작업 목적

기출모의고사(및 맞춤모의고사)의 교시별 제한시간·휴식시간을 공고 기준(1교시 법령 60분·40문항 / 휴식 20분 / 2교시 손보1부+2부 100분·80문항, 총 160분·120문항)에 맞게 정정한다.

## 4. 변경하지 않은 것 (검증 후 불필요 확인)

- **DB 스키마**: `mock_exam_sessions.part1_time_spent`/`part2_time_spent` 등은 문항 수·시간 값에 종속되지 않는 범용 컬럼 — 마이그레이션 불필요.
- **채점 로직**: `calculateScore()`는 questions 배열 기준 동적 계산 — 시간 값과 무관하게 그대로 유지.
- **문항 배분/필터링 로직**: `MockExamQuiz.jsx`의 `q.subject==='법령'` 등 필터는 그대로 유지. 애초에 40/40/40 구성이 정확했음.
- **세부과목 분류 코드**: 조대표 지시에 따라 수정 대상에서 제외.
- **타이머 소비 로직**: `mockExamStore.js`(`startExam`/`resumeExam`)가 `mockExamConfig.structure.part1/part2.timeLimit`을 그대로 읽고, `MockExamBreak.jsx`가 `mockExamConfig.breakTime`을 동적으로 읽는 구조라 config 값 수정만으로 실제 타이머 동작에 즉시 반영됨 — 로직 코드 변경 불필요.
