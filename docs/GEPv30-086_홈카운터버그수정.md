**작성일:** 2026.08.08

## 1. 작업 목적
GEPv30-085 배포 후에도 홈 대시보드의 진위형(OX) 카운터가 0으로 고정되는 문제와, 선택형(MCQ) 카운터가 실제보다 부풀려지는 문제를 Supabase DB 직접 조회로 원인 확정 후 수정.

## 2. 수정 파일
| 파일 | 변경 내용 |
|------|----------|
| `src/pages/Home.jsx` | oxTotal 쿼리의 `select('id', ...)` → `select('attempt_id', ...)`로 수정, 쿼리 실패 시 콘솔 경고 추가 |
| `src/stores/statsStore.js` | `syncFromDB()` 쿼리에 `.neq('study_mode', 'ox')` 추가 — OX 풀이가 선택형 통계에 합산되지 않도록 제외 |

## 3. 원인 (Supabase MCP로 스키마·데이터 직접 확인)

### 버그 1 — 진위형 카운터 0 고정
`public.attempts` 테이블의 실제 기본키 컬럼명은 `attempt_id`이며 `id` 컬럼은 존재하지 않는다.
```javascript
// 변경 전 — 존재하지 않는 컬럼 select → PostgREST 에러 → count는 항상 null → oxTotal 갱신 안 됨 (에러 미체크로 화면상 조용히 0 유지)
.select('id', { count: 'exact', head: true })

// 변경 후
.select('attempt_id', { count: 'exact', head: true })
.then(({ count, error }) => {
  if (error) { console.warn('[GEP] oxTotal 조회 실패:', error.message); return }
  if (count != null) setOxTotal(count)
})
```

### 버그 2 — 선택형 카운터 부풀림
`statsStore.syncFromDB()`가 `study_mode` 필터 없이 `attempts` 전체를 조회해, 단일 테이블에 함께 저장되는 OX 풀이 기록까지 선택형 통계(`bySubject`)에 합산되고 있었다.

DB 직접 조회 결과 (해당 계정 기준):
| study_mode | count |
|---|---|
| service_a_sequence | 132 |
| ox | 93 |
| service_b_subject_random | 49 |
| wrong_review | 11 |
| **합계** | **285** |

기존 화면에 표시되던 "선택형 285"는 이 전체 합계였다. `study_mode != 'ox'` 기준 실제 선택형 풀이는 192건.

```javascript
// 변경 후
const { data, error } = await supabase
  .from('attempts')
  .select('sub_subject, is_correct, question_round')
  .eq('user_id', userId)
  .neq('study_mode', 'ox')  // OX 풀이는 별도 카운터(oxTotal) — 선택형 통계에서 제외
```
