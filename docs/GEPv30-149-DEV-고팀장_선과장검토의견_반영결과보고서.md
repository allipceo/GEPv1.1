## 1. 선과장 결론 요약

GEPv30-139~145 디버깅 흐름이 "GEP 통계·이어풀기 구조의 핵심 원칙을 실제 코드에 맞춰 재정렬한 과정"이라는 총평과 함께, 4가지 방향(OX ID앵커, 정답률 누적/최근 분리, 통합오답복습 최신조회, 미니/맞춤모의고사 DB동기화)이 맞다고 확인. 다만 7개 보완사항(§2.1~2.7)과 P0/P1/P2 우선순위를 제시했다.

## 2. 항목별 검토 및 처리 결과

| 항목 | 선과장 지적 | 검토 결과 | 처리 |
|---|---|---|---|
| §2.1 토글 타임스탬프 통일 | 일부 기존 토글이 형식 불일치 | 타당. 다만 조대표가 이미 별도로 지시(제목+타임스탬프+토글+내용 순)해 신규 항목부터는 이미 통일 중 | **부분 반영** — 신규 항목은 이미 적용 중, 기존 토글 일괄 정리는 P2로 백로그 |
| §2.2 GEPv30-144 표현 정정 | "이어풀기 신설"이 아니라 "최신 원장 재계산" | 정확한 지적 — 원 문서 표현이 실제 구현과 어긋났음 | **반영 완료** — GEPv30-144에 §2-1(정책 명문화) 추가, 선과장 제안 문구 그대로 인용 |
| §2.3 questionId 파싱 공용화 | subject/sub_subject 대신 question_id를 SSOT로 삼는 공용 유틸 필요 | 타당 — GEPv30-140 회고에서도 동일 지적이 있었던 항목(중복 파싱: oxStore.js/ChallengeMode.jsx/백필SQL) | **백로그 등록** — 별도 세션에서 `parseQuestionId()` 유틸 신설 작업으로 착수(§3 참조), 지금 범위에 포함하지 않음 |

| §2.5 reset_baseline_at ↔ progress 관계 | 통계 초기화 시 이어풀기 위치도 같이 리셋할지 결정 필요 | **코드 확인 결과 이미 올바르게 분리되어 있었다** — `countingResetService.js`는 `users.reset_baseline_at`과 `reset_events`만 갱신하고 `progress` 테이블은 전혀 건드리지 않음. `Settings.jsx`의 안내문구("기존 데이터는 삭제되지 않으나 통계에서 제외됩니다")도 이미 이 분리를 정확히 반영 | **검증만 수행, 코드 변경 없음** — 선과장이 제안한 "2단계 분리 버튼" UX는 현재도 사실상 동일한 효과(진행상태는 절대 안 지워짐)이므로 별도 버튼 추가는 P2 UX 개선으로 백로그 |
| §2.6 Supabase progress 동기화 검증 시나리오 | 완료 후 state_json 잔존 시 재개 오작동 위험(P0) | 코드 확인 결과 `handleSubmit`(미니모의고사)·`submitPart1`/`submitPart2`(맞춤모의고사) 모두 완료 시 `clearProgress()`를 호출해 로컬+DB 양쪽을 지움. `saveProgress()`는 오직 "저장하고 나가기" 명시적 액션에서만 호출되고 주기적 자동저장이 없어 완료 직후 되살아나는 경합(race)도 없음 | **검증 완료, 이상 없음** — 다만 로그인 상태 실사용 검증(같은 브라우저 새로고침/재로그인)은 여전히 조대표 필요 |
| §2.7 캐시 무효화 규칙 문서화 | 표시용/출제용 캐시 정책이 암묵적으로만 존재 | 타당 | **반영 완료** — 아래 §3-1에 프로젝트 전역 캐시 정책으로 명문화 |

## 4. 백로그로 등록한 항목 (이번 범위 밖)

1. **`parseQuestionId()` 공용 유틸 신설** (P1) — question_id를 문제 메타데이터의 SSOT로 삼고, `source_type`/`round`/`subject`/`sub_subject`/`question_no`를 단일 함수에서 파싱. 현재 `oxStore.js`, `ChallengeMode.jsx`, 백필 SQL이 각자 파싱 중.
2. **설정 화면 초기화 버튼 2단계 분리 UX** (P2) — "통계 초기화"와 "학습 진행상태 초기화"를 별도 버튼으로. 현재도 기능적으로는 이미 분리되어 있으나(진행상태는 절대 안 지워짐), UI상 명시적 선택지는 없음.
3. **기존 Notion 토글 타임스탬프 일괄 정리** (P2) — 오래된 토글("개발절차" 등) 형식 통일.
4. **맞춤모의고사 완전한 타기기 이어하기 UI** (P2, GEPv30-145에서 이미 명시한 잔여과제와 동일)

## 7. 결론

선과장이 P0로 지정한 2개 항목(출제목록 캐시금지, progress 정리 검증)은 **모두 코드상 이미 올바르게 구현되어 있음을 확인**했다. P1 중 "최근10회 기준 명확화"는 문서+코드 양쪽에 반영 완료. 남은 P1(questionId 공용화)과 P2 항목들은 별도 이슈로 백로그에 등록했다.
