## 1. 작업 목적

`RequireLogin.jsx`의 승인 게이트가 `isAdmin` 여부를 고려하지 않아, 관리자 계정도 `approvalStatus !== 'approved'` 상태이면 `/service-a` 등 승인 필요 학습 라우트가 차단되는 기존 동작을 수정한다. GEPv30-092 검증 중 발견되어 이번 작업(GEPv30-094)으로 이월 처리.

## 2. 수정 파일 (1개)

| 파일 | 변경 내용 |
|------|----------|
| `src/components/RequireLogin.jsx` | `isAdmin` 구독 추가(L157) + 승인 조건에 `isAdmin` 우회 추가(L161) |

### 변경 전
```jsx
export default function RequireLogin({ children, requireApproval = true }) {
  const authStatus = useAuthStore((s) => s.authStatus)
  const approvalStatus = useAuthStore((s) => s.approvalStatus)
  const status = useAuthStore((s) => s.status)
  const isPaused = useAuthStore((s) => s.isPaused)

  if (authStatus === 'guest') return <LoginRequiredDialog />
  if (!requireApproval) return children
  if (approvalStatus === 'approved' && status === 'active' && !isPaused) return children

  return <ApprovalRequiredDialog />
}
```

### 변경 후
```jsx
export default function RequireLogin({ children, requireApproval = true }) {
  const authStatus = useAuthStore((s) => s.authStatus)
  const approvalStatus = useAuthStore((s) => s.approvalStatus)
  const status = useAuthStore((s) => s.status)
  const isPaused = useAuthStore((s) => s.isPaused)
  const isAdmin = useAuthStore((s) => s.isAdmin)

  if (authStatus === 'guest') return <LoginRequiredDialog />
  if (!requireApproval) return children
  if (isAdmin || (approvalStatus === 'approved' && status === 'active' && !isPaused)) return children

  return <ApprovalRequiredDialog />
}
```

`isAdmin`은 `src/stores/authStore.js`의 `ADMIN_EMAILS` 화이트리스트 기반으로 로그인 시점에 이미 계산되는 기존 필드(신규 로직 추가 없음). 지시대로 `isAdmin`이 참이면 `approvalStatus`/`status`/`isPaused` 상태와 무관하게 게이트를 통과한다.
