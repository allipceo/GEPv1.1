# GEPv30-006 카운팅 서비스가치 및 통계설계원칙

## 1. 문서 목적

이 문서는 GEP V3.0 1단계 서비스에서 카운팅이 단순 부가기능이 아니라 서비스의 핵심 가치임을 명확히 하기 위한 문서이다.

GEP의 문제풀이는 단순히 문제를 제공하고 정답을 알려주는 서비스가 아니다. 사용자가 자신의 현재 위치, 수준, 취약점, 앞으로 공부해야 할 방향을 스스로 깨닫게 만드는 서비스이다.

따라서 카운팅은 화면 아래에 붙는 통계가 아니라, 서비스 전체를 움직이는 중심 엔진이다.

## 2. 대표 사용자 질문

사용자는 문제를 풀면서 다음 질문에 즉시 답을 얻을 수 있어야 한다.

1. 오늘 내가 총 몇 문제를 풀었고, 그중 몇 개를 맞혔으며, 정답률은 몇 퍼센트인가?
2. 오늘 내가 푼 과목은 무엇이고, 과목별로 몇 문제를 풀었으며, 과목별 정답률은 얼마인가?
3. 이 앱을 시작한 후 오늘까지 내가 총 몇 문제를 풀었고, 전체 정답률은 어떻게 되는가?
4. 특정 과목에 대해서 지금까지 내가 총 몇 문제를 풀었고, 그 과목의 누적 정답률은 몇 퍼센트인가?
5. 내가 2번 이상 틀린 문제, 3번 이상 틀린 문제는 어느 과목에 얼마나 몰려 있는가?
6. 지금 내 공부의 방향은 어느 과목과 어느 문제군에 집중되어야 하는가?

이 질문들에 답하지 못하면 GEP V3.0은 단순 문제풀이 앱에 머문다. 이 질문들에 명확히 답할 때 비로소 수험생에게 경각심과 방향성을 주는 학습 관리 서비스가 된다.

## 3. 카운팅의 서비스 가치

카운팅의 목적은 숫자를 보여주는 것이 아니다. 사용자가 자기 상태를 자각하게 만드는 것이다.

핵심 가치는 다음과 같다.

1. 오늘의 학습량을 즉시 인식하게 한다.
2. 오늘의 과목별 편중을 확인하게 한다.
3. 누적 학습량과 전체 정답률을 확인하게 한다.
4. 과목별 누적 실력을 비교하게 한다.
5. 반복 오답 문제를 드러낸다.
6. 공부 방향을 스스로 판단하게 한다.
7. 시험일까지 남은 기간 안에서 현재 속도가 충분한지 경각심을 준다.

## 4. 필수 통계 단위

V3.0 1단계에서 반드시 필요한 통계 단위는 다음과 같다.

### 4.1 오늘 전체 통계

오늘 사용자가 푼 전체 문제 수, 정답 수, 오답 수, 정답률을 표시한다.

필수 표시값은 다음과 같다.

1. 오늘 풀이 문제 수
2. 오늘 정답 수
3. 오늘 오답 수
4. 오늘 정답률

### 4.2 오늘 과목별 통계

오늘 사용자가 어떤 과목을 얼마나 풀었는지와 과목별 정답률을 표시한다.

필수 표시값은 다음과 같다.

1. 오늘 과목별 풀이 문제 수
2. 오늘 과목별 정답 수
3. 오늘 과목별 오답 수
4. 오늘 과목별 정답률

### 4.3 누적 전체 통계

앱 사용 시작 후 현재까지의 전체 학습량과 정답률을 표시한다.

필수 표시값은 다음과 같다.

1. 누적 풀이 문제 수
2. 누적 정답 수
3. 누적 오답 수
4. 누적 정답률
5. 학습 시작일
6. 최근 풀이일

### 4.4 누적 과목별 통계

과목별로 지금까지 얼마나 풀었고 어느 과목이 취약한지 표시한다.

필수 표시값은 다음과 같다.

1. 과목별 누적 풀이 문제 수
2. 과목별 누적 정답 수
3. 과목별 누적 오답 수
4. 과목별 누적 정답률
5. 가장 취약한 과목
6. 가장 안정적인 과목

### 4.5 반복 오답 통계

사용자가 같은 문제를 반복해서 틀리는지를 추적한다.

필수 표시값은 다음과 같다.

1. 1번 틀린 문제 수
2. 2번 이상 틀린 문제 수
3. 3번 이상 틀린 문제 수
4. 과목별 2번 이상 오답 문제 비율
5. 과목별 3번 이상 오답 문제 비율
6. 반복 오답 문제 목록

### 4.6 시험 임박 반복 오답 학습

시험이 다가오면 사용자는 새 문제를 많이 푸는 것보다 이미 여러 번 틀린 문제를 집중적으로 줄이는 것이 중요하다.

따라서 V3.0은 반복 오답 횟수를 기준으로 문제를 다시 묶어 풀 수 있어야 한다.

필수 확장 기준은 다음과 같다.

1. 2회 이상 틀린 문제 다시 풀기
2. 3회 이상 틀린 문제 다시 풀기
3. 4회 이상 틀린 문제 다시 풀기
4. 5회 이상 틀린 문제 다시 풀기
5. 특정 과목 안에서 N회 이상 틀린 문제 다시 풀기
6. 전체 과목에서 N회 이상 틀린 문제 랜덤 다시 풀기
7. N회 이상 틀린 문제를 다시 맞혔을 때도 과거 오답 횟수는 보존

예를 들어 사용자는 시험 직전에 다음과 같은 학습을 할 수 있어야 한다.

1. 해상보험에서 4회 이상 틀린 문제만 다시 풀기
2. 보험업법에서 3회 이상 틀린 문제만 다시 풀기
3. 전체 과목에서 5회 이상 틀린 문제만 랜덤으로 다시 풀기
4. 오늘은 4회 이상 오답 문제만 30문제 풀기

이 기능은 파일럿 1단계에서 반드시 전체 화면으로 완성하지 않아도 된다. 그러나 데이터 구조와 카운팅 로직은 처음부터 이 기능을 지원할 수 있도록 설계해야 한다.

## 5. 데이터 기록 원칙

카운팅은 집계값을 직접 믿지 않는다. 모든 통계는 답안 제출 이벤트에서 계산 가능해야 한다.

답안 제출 1건은 최소한 다음 정보를 가져야 한다.

1. 사용자 ID
2. 문제 ID
3. 풀이 시각
4. 풀이 날짜
5. 서비스 모드
6. 회차
7. 과목
8. 세부 과목
9. 사용자가 선택한 답
10. 정답
11. 정오답 여부
12. 풀이 세션 ID
13. 초기화 기준 시점 적용 여부

화면에 표시되는 오늘 통계, 누적 통계, 과목별 통계, 반복 오답 통계는 이 답안 제출 이벤트를 기준으로 계산한다.

## 6. 화면 설계 원칙

카운팅 화면은 숫자를 많이 나열하는 화면이 아니라 사용자의 현재 위치를 알려주는 화면이어야 한다.

화면 문장은 사용자가 스스로 말하는 방식에 가깝게 구성한다.

예시는 다음과 같다.

1. 오늘 32문제를 풀었고 23문제를 맞혔습니다.
2. 오늘 정답률은 71.9%입니다.
3. 오늘은 손해보험 1부를 가장 많이 풀었습니다.
4. 누적 정답률이 가장 낮은 과목은 해상보험입니다.
5. 3번 이상 틀린 문제가 12개 있습니다.
6. 지금은 반복 오답 문제를 먼저 줄이는 것이 좋습니다.

이 화면의 목적은 사용자를 꾸짖는 것이 아니라, 현재 위치를 정직하게 보여주고 다음 행동을 안내하는 것이다.

## 7. 서비스 A와 서비스 B의 카운팅 통합

서비스 A와 서비스 B는 문제 공급 방식만 다르다.

서비스 A는 실제 기출 순서대로 문제를 제공한다. 서비스 B는 과목별 문제 풀에서 랜덤하게 문제를 제공한다. 그러나 답안 제출, 정오답 판정, 이벤트 기록, 누적 통계 계산은 반드시 같은 로직을 사용해야 한다.

이 원칙을 지키면 사용자가 어느 서비스에서 문제를 풀어도 하나의 학습 기록으로 누적된다.

## 8. 초기화 원칙

사용자 또는 운영자가 카운팅을 초기화할 수 있어야 한다.

다만 초기화는 기록을 없애는 기능이 아니라, 사용자의 현재 학습 기준선을 새로 잡는 기능으로 보는 것이 안전하다.

권장 방식은 다음과 같다.

1. 초기화 전 답안 이벤트는 보존한다.
2. 초기화 시각을 기록한다.
3. 화면 통계는 초기화 시각 이후의 이벤트만 기준으로 계산한다.
4. 운영자는 필요 시 초기화 전후 기록을 구분해 확인할 수 있다.
5. 초기화 실행자와 사유를 기록한다.

## 9. 1단계 구현 우선순위

카운팅 관련 1단계 구현 우선순위는 다음과 같다.

1. 답안 제출 이벤트 저장
2. 오늘 전체 통계
3. 오늘 과목별 통계
4. 누적 전체 통계
5. 누적 과목별 통계
6. 문제별 오답 횟수
7. 2번 이상, 3번 이상 반복 오답 분류
8. N회 이상 반복 오답 필터 기준
9. 과목별 N회 이상 반복 오답 다시 풀기 연결
10. 카운팅 초기화
11. 운영자 확인 화면

고급 차트와 예측 기능은 1단계 이후로 미룬다. 1단계에서는 숫자가 정확하고 사용자가 바로 이해할 수 있는 것이 더 중요하다.

## 10. 결론

GEP V3.0의 핵심은 문제 제공이 아니다. 핵심은 사용자가 문제를 풀 때마다 자신의 현재 위치를 더 선명하게 알게 되는 것이다.

따라서 카운팅은 다음 원칙으로 개발한다.

**모든 풀이를 기록하고, 모든 통계는 기록에서 계산하며, 모든 화면은 사용자가 자신의 수준과 공부 방향을 깨닫게 만드는 데 집중한다.**
