# GEPv30-014 로컬빈화면오류 원인분석 및 조치보고서

## 1. 발생 상황

2026년 8월 5일 로컬 개발 서버 실행 후 `http://127.0.0.1:5173/`에 접속했으나 화면이 표시되지 않는 문제가 발생했다.

## 2. 점검 결과

점검 결과는 다음과 같다.

1. Vite 개발 서버는 정상 실행 중이었다.
2. `http://127.0.0.1:5173/` 요청은 HTTP 200으로 응답했다.
3. `npm run build`는 성공했다.
4. 로컬 저장소에 `.env.local` 파일이 없었다.
5. 개발 서버의 `import.meta.env`에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`가 없었다.
6. `createClient(undefined, undefined)` 실행 시 `supabaseUrl is required` 예외가 발생했다.

## 3. 원인

빈 화면의 원인은 Supabase 환경변수 누락이다.

기존 `src/lib/supabase.js`는 앱 초기화 시점에 다음 값을 즉시 사용했다.

1. `import.meta.env.VITE_SUPABASE_URL`
2. `import.meta.env.VITE_SUPABASE_ANON_KEY`

로컬 `.env.local`이 없는 상태에서는 두 값이 `undefined`가 되고, Supabase 클라이언트 생성 함수가 예외를 발생시켜 React 앱이 첫 렌더링 전에 중단되었다.

## 4. 조치 내용

`src/lib/supabase.js`에 Supabase 환경변수 누락 안전장치를 추가했다.

변경 내용은 다음과 같다.

1. `isSupabaseConfigured` 플래그 추가
2. 환경변수가 있으면 기존처럼 실제 Supabase 클라이언트 생성
3. 환경변수가 없으면 앱이 죽지 않도록 비활성 Supabase 클라이언트 제공
4. 비활성 클라이언트는 인증 세션을 `guest`로 처리
5. DB 요청은 명확한 오류 메시지를 반환

`src/components/LoginButton.jsx`도 보강했다.

1. Supabase 환경변수가 없을 때 OAuth 요청을 시도하지 않는다.
2. 대신 `.env.local` 설정이 필요하다는 안내창을 표시한다.

## 6. 남은 운영 전제

로컬 화면은 이제 빈 화면으로 죽지 않는다.

다만 실제 로그인, 승인 요청 저장, 운영자 승인 기능을 완전히 테스트하려면 다음 설정이 필요하다.

1. `.env.local`에 `VITE_SUPABASE_URL` 설정
2. `.env.local`에 `VITE_SUPABASE_ANON_KEY` 설정
3. Supabase 운영 DB에 `007_v3_pilot_approval.sql` 실행
4. `gep_admin_emails`에 운영자 이메일 등록
5. `VITE_GEP_ADMIN_EMAILS`에 운영자 이메일 설정

## 7. 결론

이번 빈 화면 문제는 코드 문법이나 빌드 실패가 아니라 로컬 Supabase 환경변수 누락으로 발생했다.

앱이 환경변수 누락 때문에 완전히 죽지 않도록 안전장치를 추가했고, 홈 화면 렌더링과 미로그인 문제풀이 차단 팝업을 자체 테스트로 확인했다.
