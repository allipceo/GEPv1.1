## 1. 신고 내용 (원문 요약)

계정 `202504012` (사번) / `20676442`(비밀번호)로 크롬에서 문제 풀이 중,
1. 로그아웃 후 재로그인 시도 → 크롬이 먹통이 되고 로그인이 안 됨. 크롬 재시작으로도 해결 안 됨.
2. F12 → 애플리케이션 → 모든 데이터 삭제 후에만 로그인 가능.
3. 단, 데이터 삭제 후 재로그인하면 회차별 풀이 진도(예: 23회 12/120)가 0/120으로 초기화됨.

## 2. 원인 분석

### 버그 A — 로그아웃 후 로그인 먹통

`src/pages/Home.jsx` `handleLogout()`:

```jsx
useAuthStore.getState().clearAuth()
await supabase.auth.signOut({ scope: 'global' })
...
window.location.href = '/'   // ← 강제 풀 리로드
```

`signOut()` 완료 직후 곧바로 강제 풀 리로드를 실행한다. Supabase Auth 클라이언트(GoTrueClient)는 내부적으로 Navigator LockManager로 인증 작업(로그인/로그아웃/토큰 갱신)을 직렬화하는데, 리로드가 이 잠금 해제 타이밍과 겹치면 잠금이 반납되지 않고 붕 뜨는 경우가 있다. 이후 `signInWithPassword` 호출은 이 잠금을 무한 대기하게 되어 로그인 버튼이 "로그인 중..." 상태에서 멈추고 화면 전체가 응답하지 않는 것처럼 보인다. 브라우저를 재시작해도 같은 프로필의 저장소(storage partition)에 잠금 관련 상태가 남아있어 재현되고, `사이트 데이터 삭제`만이 이 상태를 완전히 리셋한다.

이 프로젝트는 동일 계열 증상("SW/LockManager 충돌 → 로그인 불가")으로 이미 2회 긴급수정 이력이 있다 (`docs/GEP_111_SW_긴급수정_캐시버전갱신.md`, `public/sw.js` 주석의 GEPv30-080). Service Worker 쪽 원인(Supabase 요청을 SW가 가로채던 문제)은 이미 해소되어 있으나, `signOut → 강제 리로드` 패턴 자체가 같은 계열의 잠금 충돌을 재유발하는 것으로 판단된다.

### 버그 B — 회차별 풀이 진도 리셋

`ServiceAHome.jsx`가 표시하는 진도(`progressMap['service_a_{round}']`)는 `src/stores/examStore.js`에서 **오직 localStorage**(`gep:v1:examStore:{userId}`)로만 관리된다.

반면 Supabase에는 이미 `progress` 테이블이 존재하고(`supabase/schema.sql:103`, `user_id + filter_key + current_index`, UNIQUE 제약), `examStore.setCurrentIndex()`가 풀이할 때마다 fire-and-forget으로 이 테이블에 upsert하고 있다 (`examStore.js:305-321`).

**문제는 로그인 시 이 서버 데이터를 다시 읽어와 `progressMap`에 복원하는 코드가 없다는 것.** `statsStore.syncFromDB()`가 선택형/진위형 통계를 DB에서 복원하는 것과 동일한 패턴이 `examStore`에는 빠져 있다. 따라서 localStorage가 지워지면(사이트 데이터 삭제, 기기 변경, 브라우저 재설치 등) 서버에는 진도가 정상적으로 남아있음에도 화면은 0/120으로 표시된다 — **데이터 유실이 아니라 "DB 복원 로직 누락"**이다.

## 3. 수정 계획

| # | 파일 | 변경 내용 |
|---|------|----------|
| 1 | `src/pages/Home.jsx` | `handleLogout()`의 `window.location.href = '/'` → `navigate('/', { replace: true })`로 교체 (강제 풀 리로드 제거, SPA 네비게이션으로 전환). `SIGNED_OUT` 이벤트는 이미 `authStore.initAuthListener`가 처리하므로 풀 리로드가 불필요함 |
| 2 | `src/components/LoginButton.jsx` | `signInWithPassword` 호출에 타임아웃 가드(10초) 추가 — 향후 동일 계열 잠금 문제가 재발해도 버튼이 무한 대기하지 않고 "응답 지연" 안내로 전환되도록 방어 |
| 3 | `src/stores/examStore.js` | `syncProgressFromDB(userId)` 함수 신규 추가 — `progress` 테이블에서 `(filter_key, current_index)` 조회, 로컬 `progressMap`과 병합(더 큰 값 우선, `statsStore.syncFromDB`와 동일한 병합 정책) 후 localStorage에 저장 |
| 4 | `src/App.jsx` | `userId` 변경 시점(로그인 완료 시점) `useEffect`에서 `syncProgressFromDB(userId)` 호출 추가 |

### 위험 요소 및 완화

- **`scope: 'global'` 유지 여부**: 다른 기기의 세션까지 로그아웃시키는 정책은 과거 "자동 로그인 잔류" 버그 방지를 위해 의도적으로 도입된 것으로 판단되어(CLAUDE.md 교훈 항목) **그대로 유지**한다. 이번 수정은 `signOut()` 자체가 아니라 그 직후의 "강제 리로드" 타이밍만 제거하는 것이므로 기존 정책과 충돌하지 않는다.
- **SPA 네비게이션 전환 시 잔존 상태 우려**: `window.location.href`를 제거하면 이전 세션의 컴포넌트 트리(예: 문제풀이 화면)가 완전히 언마운트되지 않을 가능성이 있음 → `authStore.clearAuth()` + `App.jsx`의 `userId` 변경 effect가 이미 `examStore`/`statsStore`를 guest 상태로 재바인딩하므로 상태 오염 위험은 낮음. 검증 단계에서 로그아웃 후 홈 화면이 게스트 상태로 정확히 전환되는지 별도 확인.
- **progress 복원 시 병합 정책**: DB 값과 로컬 값 중 **더 큰 값**을 채택 (statsStore와 동일). 오프라인 상태에서 로컬에만 진행한 풀이가 DB sync 이전에 로그아웃되는 극단적 케이스에서도 로컬 진행이 손실되지 않도록 함.
