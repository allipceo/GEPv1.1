# GEPv30-019 서비스B 과목별랜덤풀이 구현보고서

- 작성일: 2026-08-05
- 대상: GEP V3.0 1단계 파일럿 서비스 B
- 브랜치: gepv30-phase1-pilot
- 테스트 URL: http://127.0.0.1:5173/

## 1. 구현 목적

서비스 B는 23~31회 기출문제를 과목 또는 세부과목별로 묶고, 선택한 범위 안에서 랜덤 순서로 문제를 제공하는 학습 서비스다.

이번 구현의 목표는 다음과 같다.

1. 홈에서 서비스 B 진입점을 명확히 제공한다.
2. 서비스 B 전용 화면에서 과목/세부과목을 선택하게 한다.
3. 선택한 문제 풀 안에서 랜덤 순서를 생성한다.
4. 이어풀기와 새 랜덤 시작을 분리한다.
5. 기존 공통 문제풀이 화면과 Phase4 카운팅 계약을 재사용한다.

## 2. 데이터 확인

현재 `public/data/exams.json` 기준 서비스 B 문제 풀은 다음과 같다.

| 과목 | 총문제 | 세부과목 |
|---|---:|---|
| 법령 | 360 | 보험업법 90, 상법 180, 위험관리 45, 세제재무 45 |
| 손보1부 | 360 | 자동차보험 135, 특종보험 90, 보증보험 45, 연금저축 90 |
| 손보2부 | 360 | 화재보험 90, 해상보험 135, 항공우주 45, 재보험 90 |

총 문항 수는 1,080문제이며, 서비스 A와 동일하게 현재 데이터는 23~31회 9개 회차 기준이다.

## 3. 주요 변경사항

### 3.1 서비스 B 라우트 추가

- 추가 파일: `src/pages/ServiceBHome.jsx`
- 변경 파일: `src/App.jsx`
- 추가 라우트: `/service-b`

`/service-b`는 `RequireLogin`으로 보호된다. 로그인하지 않은 사용자는 서비스 B 화면을 볼 수 없고 등록 요구 화면으로 안내된다.

### 3.2 홈 진입 버튼 추가

- 변경 파일: `src/pages/Home.jsx`

홈 화면에 `과목별 랜덤풀이` 버튼을 추가했다.

- 표시 문구: `과목별 랜덤풀이`
- 보조 문구: `서비스 B`
- 클릭 시: `/service-b` 이동

기존 홈의 과목 아코디언 세부과목 클릭도 `startServiceB()`를 사용하도록 연결했다.

### 3.3 랜덤 문제 공급 로직

- 변경 파일: `src/stores/examStore.js`

서비스 B를 위해 다음 상태와 로직을 정리했다.

- `questionOrder`: 랜덤 문제 ID 순서 저장
- `startServiceB(subject, subSubject, options)`
- `makeServiceBKey(subject, subSubject)`
- `shuffleIds(items)`

서비스 B 규칙은 다음과 같다.

1. `studyMode === 'service_b_subject_random'`
2. 선택한 과목 또는 세부과목 문제만 필터링
3. 선택 범위 안에서 문제 ID를 셔플해 `questionOrder`에 저장
4. 이어풀기는 기존 `questionOrder`와 진행 인덱스를 재사용
5. 새 랜덤은 진행 인덱스를 0으로 돌리고 새 `questionOrder` 생성

### 3.4 진행도 키 분리

서비스 B 진행도 키는 다음 형식이다.

- 과목 전체: `service_b_{subject}_ALL`
- 세부과목: `service_b_{subject}_{subSubject}`

서비스 A의 `service_a_{round}`와 분리되어 서로의 이어풀기 상태가 섞이지 않는다.

## 5. 레드팀 점검

### 통과한 항목

1. 서비스 B 진입점이 홈에 표시된다.
2. 서비스 B는 로그인/승인 보호 라우트 안에 있다.
3. 과목/세부과목별 문제 풀을 구성할 수 있다.
4. 새 랜덤과 이어풀기 흐름이 분리된다.
5. 서비스 A와 서비스 B의 진행도 키가 섞이지 않는다.
6. 답안 제출은 기존 공통 `recordAttempt` 계약을 사용한다.

### 보류 항목

실제 승인 사용자로 다음 항목은 Supabase 연결 후 검증해야 한다.

1. 승인 사용자의 `/service-b` 화면 진입
2. 과목 전체 새 랜덤 시작
3. 세부과목 새 랜덤 시작
4. 이어풀기 재진입 시 기존 랜덤 순서 유지
5. 답안 제출 후 `attempts.study_mode = service_b_subject_random` 저장
6. 서비스 B 진행도 저장
