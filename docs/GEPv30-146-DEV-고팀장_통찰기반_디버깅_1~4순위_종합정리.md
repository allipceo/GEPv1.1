## 1. 배경

GEPv30-141 통찰보고서가 정의한 6개 서비스(MCQ A/B, OX, 모의고사, 미니모의고사, 맞춤모의고사, 오답복습)의 통계·이어풀기 감사 결과를 바탕으로, §5에서 제안한 우선순위 1~4를 순서대로 구현했다. 각 항목은 조사 → 설계 판단 → 구현 → 빌드검증 → 비로그인 스모크 테스트 → 문서화 → 개별 커밋의 동일한 절차를 따랐다.

## 2. 항목별 요약

### 우선순위 1 — OX 이어풀기 ID 앵커 전환 ([GEPv30-142](GEPv30-142-DEV-고팀장_OX이어풀기_ID앵커전환_구현결과보고서.md))

- **문제:** 직전 세션(GEPv30-139)에서 연결한 OX 이어풀기가 `progress.current_index`(순수 정수)를 저장 — 문제 세트 구성이 바뀌면 엉뚱한 문제를 가리킬 위험(원칙 9 위반).
- **조치:** `progress.last_question_id`(text) 컬럼 신설. 재개 시 현재 로드된 문제 목록에서 이 ID의 위치를 다시 찾아 그 지점부터 시작, 못 찾으면 0번으로 안전 폴백.
- **수정 파일:** `oxService.js`, `oxStore.js`, `OXSubject.jsx` + 마이그레이션 `add_last_question_id_to_progress`
- **커밋:** `4c74aa6`

### 우선순위 2 — 정답률 "최근 10회" 추가 ([GEPv30-143](GEPv30-143-DEV-고팀장_정답률_최근10회_구현결과보고서.md))

- **문제:** 정답률이 전체누적만 있고 최근 흐름을 구분하지 못함(원칙 11 위반). 조대표 확인 결과 기준 = 최근 10회.
- **조사:** `StatsPanel.jsx`의 homeMode 3과목별 정답률은 실제로 어디서도 렌더링되지 않는 죽은 코드였음을 확인. 실제 표시 위치는 Home.jsx의 선택형/진위형 카드뿐이었음.
- **조치:** Home.jsx에 `attempts` 원장 기준 최근 10건 조회 useEffect 추가, 기존 누적 정답률 옆에 "최근10회 N%" 표시.
- **수정 파일:** `Home.jsx`
- **커밋:** `ee0aacd`

### 우선순위 3 — 통합오답복습 동적목록 신선도 ([GEPv30-144](GEPv30-144-DEV-고팀장_통합오답복습_동적목록신선도_구현결과보고서.md))

- **문제 재정의:** 당초 "이어풀기 위치 저장"이 필요하다고 봤으나, 실제로는 `ChallengeMode.jsx`가 `getCachedWrongQuestions`(캐시 전용, 미스 시 빈 배열)만 호출하는 버그였음. 캐시 만료 시 실제 오답이 있어도 0문제로 오탐, 캐시 생존 시(1시간 TTL) 세션 중 해결한 문제가 재진입 시 그대로 재등장.
- **설계 판단:** 이 목록은 매번 `attempts` 원장에서 재계산되는 자기치유적 구조라, "위치 저장"이 아니라 "항상 최신 조회"가 정답. 인덱스/ID를 저장할 필요가 없다는 점을 확인.
- **조치:** `fetchAllWrongQuestions(userId, { bypassCache: true })`로 전환.
- **수정 파일:** `unifiedWrongService.js`, `ChallengeMode.jsx`
- **커밋:** `a18cb7b`

### 우선순위 4 — 미니/맞춤 모의고사 DB 동기화 ([GEPv30-145](GEPv30-145-DEV-고팀장_미니맞춤모의고사_DB동기화_구현결과보고서.md))

- **문제:** 진행상황 저장이 localStorage 전용 — 기기 변경·브라우저 데이터 삭제 시 진행 중 세션 유실.
- **조치:** `progress.state_json`(jsonb) 컬럼 신설 + `genericProgressService`(신규)로 answers/currentIndex/elapsedTime을 로컬+Supabase 양쪽 저장, 재진입 시 `savedAt` 기준 더 최신 쪽 채택. 맞춤모의고사는 기기마다 달라지는 `sessionLocalId` 대신 서버 발급 `supabaseSessionId`를 조회키로 재사용.
- **회귀 방지:** `MiniMockHome.jsx`의 "처음부터 다시 풀기" 버튼이 로컬만 지우고 DB는 안 지우던 것을 발견해 `store.clearProgress()`(로컬+DB 동시 삭제)로 교체 — 그렇지 않으면 재시작 후에도 DB의 예전 진행분이 "더 최신"으로 오인되어 되살아나는 회귀가 생겼을 것.
- **범위 밖으로 명시:** 맞춤모의고사의 완전한 타기기 이어하기(세션메타 자체가 없는 새 기기에서 복원)는 `CustomMockHome.jsx`에 신규 UI가 필요한 별도 작업 — 데이터는 이미 서버에 있으므로 추후 UI만 얹으면 됨.
- **수정 파일:** `genericProgressService.js`(신규), `miniMockStore.js`, `MiniMockQuiz.jsx`, `MiniMockHome.jsx`, `customMockStore.js`, `CustomMockQuiz.jsx` + 마이그레이션 `add_state_json_to_progress`
- **커밋:** `653b52b`

## 3. 공통 검증 방법 (4개 항목 동일 적용)

1. `npm run build` 성공 확인
2. 비로그인 스모크 테스트 — 해당 라우트 콘솔에 **새로 발생한** 에러가 없는지 확인(Supabase Navigator LockManager 타임아웃은 이 개발환경에 기존부터 있던 무관한 노이즈로, 각 항목에서 매번 동일하게 관찰되어 회귀가 아님을 확인함)
3. 문서화(DOCS + git 추적 docs/ 양쪽) 후 개별 커밋

**로그인 상태 실사용 검증은 아직 완료되지 않았다** — 4개 항목 모두 조대표 본인 브라우저에서 확인이 필요한 상태다(각 문서 §검증 절 참조).
