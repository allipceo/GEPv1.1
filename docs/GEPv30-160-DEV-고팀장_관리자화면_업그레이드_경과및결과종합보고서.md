## 3. 발생 이슈와 해결

### 3-1. 지시서 스키마 불일치 (GEPv30-157)

지시서 표기와 실 DB가 달라 개발 전 Supabase 스키마를 직접 조회해 정정.

| 지시서 | 실제 | 조치 |
|--------|------|------|
| `attempts.id` | `attempt_id` | 쿼리 정정 |
| `attempts.created_at` | `attempted_at` | 날짜 집계 컬럼 정정 |
| `MODE_LABEL: service_a / service_b` | `service_a_sequence` / `service_b_subject_random` / `ox` / `mini_mock` / `wrong_review` / `unified_wrong_challenge` | 라벨맵 실값 기준 재작성 |
| 참가자 12명 | 실제 14명 | 하드코딩 제거, 쿼리 결과대로 렌더 |

### 3-2. 🔴 attempts RLS로 관리자 교차조회 불가 → 선택지 A 적용

`attempts` 정책이 `attempts_self (auth.uid() = user_id)` 하나뿐 → 관리자도 본인 행만 조회됨.
조대표 승인(2026-09-04)으로 **선택지 A** 채택:

```sql
-- supabase/migrations/017_attempts_admin_select.sql (원격 DB 적용 완료)
CREATE POLICY attempts_admin_select ON public.attempts
  FOR SELECT USING (public.gep_is_admin());
```
- 기존 `users_admin_select`와 동일 패턴, `gep_is_admin()` 재사용
- permissive 정책 OR 결합 → 관리자=전체 조회 / 일반 사용자=본인만 (동작 불변)
- 롤백: `DROP POLICY attempts_admin_select ON public.attempts;`

### 3-3. 집계 범위에 개시 전 데이터 혼입 → 파일럿 기간 한정

`총 풀이 수`가 개발·테스트 데이터 포함 1,407건으로 표시되어 파일럿 실태를 왜곡.
조대표 지시로 전 패널을 `attempted_at >= 2026-09-02T15:00:00Z`(= 2026-09-03 00:00 KST) 이후로 한정.
헤더에 "집계 기간: 파일럿 개시(2026-09-03) ~ 현재" 명시.
