# 01_GEPv3.0 기획서

## 1. 기획 목적

GEPv3.0은 이미 모바일과 웹에서 작동 중인 GEP V2.0 완성 앱을 기준으로, 보험중개사 시험 준비자를 위한 기출문제 학습 서비스를 운영 가능한 제품 수준으로 고도화하는 프로젝트이다.

V1.0과 V2.0에서 축적된 기출문제 데이터, 작동 UI, 사용자 시나리오, 통계 구조, 레고블록 개발철학을 계승하되, V3.0에서는 다음 목표를 우선한다.

1. 보험중개사 시험 합격에 직접 도움이 되는 학습 흐름 완성
2. 무료, 기본, 고급 서비스의 상품 구조 명확화
3. 문제 데이터 관리와 서비스 운영 구조 단순화
4. 기존 기출문제 자산을 안전하게 활용하는 중앙 데이터 구조 확립
5. V2.0의 작동 기능을 기준으로 빠르게 검증 가능한 고도화 로드맵 수립

## 2. V3.0 핵심 방향

### 2.1 제품 방향

GEPv3.0은 단순 문제풀이 앱이 아니라, 보험중개사 시험 수험생이 자신의 현재 수준을 확인하고, 취약 과목을 반복 보완하며, 시험일까지 합격 가능성을 높이는 학습 관리 서비스로 정의한다.

핵심 사용자 가치는 다음과 같다.

1. 기출문제를 회차별, 과목별로 안정적으로 풀 수 있다.
2. 푼 기록이 사라지지 않고 이어풀기가 가능하다.
3. 틀린문제를 틀린 횟수별로 다시 풀 수 있다.
4. 일일, 누적, 과목별 통계로 학습 상태를 확인할 수 있다.
5. 미니모의고사를 통해 실제 시험 감각을 연습할 수 있다.
6. 시험일까지 남은 기간과 현재 정답률을 기준으로 합격 가능성을 예측할 수 있다.

### 2.2 개발 방향

V3.0 개발은 기존 문서에서 확인된 4대 원칙을 그대로 유지한다.

1. 탑다운: 고급 서비스의 완성 모습을 먼저 확정하고, 무료와 기본 서비스는 기능 제어로 구성한다.
2. 레고블록: 문제풀이, 통계, 사용자, 오답, 모의고사를 독립 블록으로 만든다.
3. 중앙아키텍처: 문제, 사용자, 이벤트, 진행, 통계 데이터의 기준점을 중앙에서 관리한다.
4. 원소스멀티유즈: 하나의 문제 데이터와 하나의 문제풀이 UI를 여러 서비스 레벨에서 재사용한다.

V3.0에서는 여기에 하나의 원칙을 추가한다.

5. 단순 실행 구조: 사용자 가치가 낮은 과도한 모듈, 과도한 최적화, 과도한 관리 클래스를 만들지 않는다.

## 3. 기존 자산 분석

### 3.0 현재 작동 원천 저장소

현재 배포되어 작동 중인 GEP 앱의 원천 저장소는 다음으로 본다.

1. GitHub 저장소: `allipceo/GEPv1.1`
2. 배포 URL: `https://gepv11.vercel.app/`
3. 기술 스택: Vite, React, Zustand, Supabase, Vercel
4. 객관식 데이터: 23회부터 31회까지 총 1,080문항
5. OX 데이터: 총 3,824문항

저장소 이름은 V1.1이지만, 현재 실제 작동 앱의 원천으로 확인되었으므로 V3.0은 이 저장소를 기준으로 고도화한다.

### 3.1 보유 데이터 자산

현재 작업공간에는 보험중개사 시험 다년치 문제 및 답안 자료가 포함되어 있으며, 배포 중인 GEP V2.0 앱에서는 모의고사 화면 기준 23회부터 31회까지의 회차가 표시된다. V3.0에서는 작업공간 원천 파일 범위와 실제 서비스 표시 범위를 먼저 대조하여 최종 데이터 범위를 확정한다.

주요 자산은 다음과 같다.

1. 10년 이상 기출문제 PDF
2. 회차별 확정답안 PDF
3. 문제 마스터 엑셀 파일
4. 기존 변환 결과 엑셀 파일
5. QCODE 및 과목 분류 관련 문서
6. V1.0, V2.0 개발 계획서와 완료보고서
7. 현재 배포 중인 V2.0 모바일/웹 앱 UI

V3.0은 이 자산을 새로 만들지 않고, V2.0에서 이미 작동하는 UI와 검증된 데이터를 정리하여 마스터 데이터베이스와 운영 가능한 서비스 구조로 편입하는 방향으로 진행한다.

### 3.2 기존 개발 교훈

기존 문서에서 확인된 핵심 교훈은 다음과 같다.

1. 기존 검증 코드와 데이터를 먼저 활용한다.
2. QUESTION 필드는 원문 보존을 원칙으로 한다.
3. 사용자 시나리오와 UI를 먼저 확정한 뒤 데이터 구조를 설계한다.
4. 중앙 데이터 관리자를 기준으로 데이터 불일치를 방지한다.
5. 기능을 너무 잘게 나눈 파일 구조는 오히려 개발 속도와 유지보수를 해친다.
6. 복잡한 수정 루프에 빠지면 되돌아가서 단순 구조로 재정렬한다.

## 4. 대상 사용자

### 4.1 핵심 사용자

1. 보험중개사 시험을 처음 준비하는 수험생
2. 최근 기출문제를 반복해서 풀고 싶은 수험생
3. 과목별 취약점을 확인하고 싶은 수험생
4. 시험일까지 학습 진도와 합격 가능성을 관리하고 싶은 수험생

### 4.2 운영자

운영자는 조대표님을 기준으로 한다. 운영자는 다음 업무를 수행한다.

1. 신규 회차 PDF 확보
2. PDF를 엑셀로 변환
3. 문제와 정답 검증
4. QCODE 규칙에 따른 신규 문제 등록
5. 서비스 데이터 업데이트 승인

## 5. 서비스 레벨

### 5.1 무료 서비스

목적은 사용자가 서비스를 체험하고 기본 문제풀이 흐름을 이해하게 하는 것이다.

제공 기능은 다음과 같다.

1. 최신 회차 기출문제 순차 풀이
2. 최신 회차 중 1개 과목 문제 순차 풀이
3. 답안 제출 후 정답 확인
4. 기본 결과 요약
5. 기본 또는 고급 서비스 전환 안내

제한 기능은 다음과 같다.

1. 전체 회차 선택 제한
2. 전체 과목 선택 제한
3. 상세 통계 제한
4. 틀린문제 학습 제한
5. 미니모의고사 제한

### 5.2 기본 서비스

목적은 실제 수험생이 매일 사용할 수 있는 기본 학습 환경을 제공하는 것이다.

제공 기능은 다음과 같다.

1. 회차별 기출문제 선택 풀이
2. 과목별 기출문제 선택 풀이
3. 이어풀기
4. 일일 통계
5. 누적 통계
6. 과목별 정답률
7. 전체 평균과 과목 평균 기반 합격 가능성 예측
8. 사용자 등록, 시험일, D-day 관리

### 5.3 고급 서비스

목적은 합격 가능성을 높이는 반복 학습과 진단 학습을 제공하는 것이다.

제공 기능은 다음과 같다.

1. 기본 서비스 전체 기능
2. 틀린문제 틀린 횟수별 학습
3. 기출문제 기반 미니모의고사
4. 20문제, 30문제, 40문제, 50문제, 60문제 모의고사 구성
5. 과목 비율 기반 문제 자동 구성
6. 고급 통계
7. 취약 과목 분석
8. 학습 개선 방향 제안

## 6. 핵심 사용자 시나리오

### 6.1 신규 사용자 등록

1. 사용자가 앱에 처음 접속한다.
2. 게스트 또는 사용자 등록 화면이 열린다.
3. 게스트는 전화번호만 입력한다.
4. 기본 또는 고급 사용자는 성명, 전화번호, 응시일, 시험명을 입력한다.
5. 응시일 미입력 시 기본값은 1년 후로 설정한다.
6. 등록 시점부터 모든 학습 이벤트와 통계가 생성된다.
7. 사용자가 앱을 다시 열면 전화번호 기준으로 기존 학습 기록을 불러온다.

### 6.2 회차별 문제풀이

1. 사용자가 회차별 문제풀이를 선택한다.
2. 서비스 레벨에 따라 선택 가능한 회차가 표시된다.
3. 사용자가 회차를 선택한다.
4. 기존 진행 기록이 있으면 마지막 풀이 다음 문제부터 시작한다.
5. 답안을 제출하면 정답 여부가 표시된다.
6. 이벤트 로그, 진행 기록, 통계가 동시에 갱신된다.

### 6.3 과목별 문제풀이

1. 사용자가 과목별 문제풀이를 선택한다.
2. 서비스 레벨에 따라 선택 가능한 과목이 표시된다.
3. 사용자가 과목을 선택한다.
4. 기존 진행 기록이 있으면 마지막 풀이 다음 문제부터 시작한다.
5. 답안을 제출하면 과목별 통계와 누적 통계가 갱신된다.

### 6.4 틀린문제 학습

1. 고급 사용자가 틀린문제 학습을 선택한다.
2. 시스템이 사용자 이벤트 로그를 기준으로 전체 오답 이력을 분석한다.
3. 기출문제와 객관식문제를 구분한다.
4. 1회, 2회, 3회, 4회, 5회, 6회 이상 틀린 문제 묶음을 표시한다.
5. 사용자가 특정 묶음을 선택한다.
6. 해당 문제들을 이어풀기 방식으로 제공한다.
7. 다시 틀리면 틀린 횟수가 증가하고 분류가 자동 이동한다.

### 6.5 미니모의고사

1. 고급 사용자가 미니모의고사를 선택한다.
2. 20문제, 30문제, 40문제, 50문제, 60문제 중 하나를 선택한다.
3. 시스템이 실제 시험 과목 비율에 맞춰 문제를 구성한다.
4. 사용자가 제한 시간 안에 문제를 푼다.
5. 제출 후 전체 점수, 과목별 점수, 합격 여부, 취약 과목을 표시한다.
6. 결과는 모의고사 세션 기록과 통계에 저장된다.

## 7. 데이터 구조

V3.0은 데이터베이스를 처음부터 크게 만들지 않고, MVP 기준 5개 핵심 데이터부터 시작한다.

### 7.1 MVP 핵심 데이터

1. `questions_master`: 문제 원천 데이터
2. `users`: 사용자 등록 및 서비스 레벨 데이터
3. `learning_events`: 사용자의 모든 답안 제출 이벤트
4. `learning_progress`: 회차별, 과목별 이어풀기 지점
5. `statistics`: 일일, 누적, 과목별 통계

### 7.2 고급 기능 확장 데이터

1. `wrong_question_summary`: 틀린 횟수별 문제 분류
2. `mini_exam_templates`: 미니모의고사 구성 규칙
3. `mini_exam_sessions`: 모의고사 실행 및 결과 기록
4. `service_level_history`: 게스트에서 유료 서비스로 전환된 이력

### 7.3 데이터 원칙

1. 문제 원문 필드는 수정하지 않는다.
2. QCODE는 문제의 고유 식별자로 사용한다.
3. 사용자는 전화번호를 기준으로 식별한다.
4. 통계는 이벤트 로그에서 재계산 가능해야 한다.
5. 진행 데이터는 빠른 조회를 위한 캐시 성격으로 관리한다.
6. 데이터 불일치가 발생하면 이벤트 로그를 기준으로 복구한다.

## 10. 개발 단계

### Phase 0. 데이터 점검 및 마스터 확정

목표는 V3.0 개발 전에 문제 데이터 기준을 확정하는 것이다.

작업은 다음과 같다.

1. 기존 엑셀 마스터 후보 식별
2. QCODE 중복 여부 점검
3. 회차, 과목, 세부과목 필드 정리
4. 정답 필드 검증
5. QUESTION 필드 원문 보존 확인
6. `questions_master.json` 생성

산출물은 다음과 같다.

1. `data/questions_master.json`
2. 데이터 검증 보고서
3. QCODE 오류 목록

### Phase 1. MVP 학습 서비스 구현

목표는 등록, 홈, 회차별 풀이, 과목별 풀이, 정답 확인, 이어풀기를 완성하는 것이다.

작업은 다음과 같다.

1. 사용자 등록 화면 구현
2. 홈 대문 구현
3. 문제 로딩 API 구현
4. 답안 제출 API 구현
5. 회차별 문제풀이 구현
6. 과목별 문제풀이 구현
7. 이어풀기 구현

성공 기준은 다음과 같다.

1. 신규 사용자가 등록 후 문제를 풀 수 있다.
2. 답안 제출 시 정답 여부가 표시된다.
3. 앱을 다시 열어도 이어풀기가 된다.
4. 이벤트 로그가 누락 없이 저장된다.

### Phase 2. 기본 통계 및 합격 예측

목표는 기본 서비스의 핵심 가치를 완성하는 것이다.

작업은 다음과 같다.

1. 일일 통계 계산
2. 누적 통계 계산
3. 과목별 정답률 계산
4. 회차별 정답률 계산
5. D-day 표시
6. 간단 합격 가능성 예측
7. 통계 화면 구현

성공 기준은 다음과 같다.

1. 통계가 이벤트 로그와 일치한다.
2. 과목별 취약점이 표시된다.
3. 사용자가 오늘 얼마나 풀었는지 즉시 알 수 있다.

### Phase 3. 고급 서비스 구현

목표는 고급 서비스의 핵심 상품 가치를 완성하는 것이다.

작업은 다음과 같다.

1. 틀린문제 분석
2. 틀린 횟수별 문제 분류
3. 틀린문제 이어풀기
4. 미니모의고사 템플릿 구현
5. 미니모의고사 문제 구성 알고리즘
6. 모의고사 결과 저장
7. 고급 통계 화면 구현

성공 기준은 다음과 같다.

1. 틀린문제 분류가 이벤트 로그 기준으로 정확하다.
2. 다시 틀린 문제의 틀린 횟수가 자동 증가한다.
3. 미니모의고사가 과목 비율에 맞게 구성된다.
4. 모의고사 결과가 통계에 반영된다.

### Phase 4. 운영 도구 및 배포 준비

목표는 조대표님이 직접 문제를 추가하고 서비스를 운영할 수 있게 만드는 것이다.

작업은 다음과 같다.

1. 엑셀에서 JSON 변환 도구 정리
2. 신규 회차 데이터 검증 도구 구현
3. 통계 재계산 도구 구현
4. 데이터 백업 절차 문서화
5. 수동 테스트 체크리스트 작성
6. 배포 준비

성공 기준은 다음과 같다.

1. 신규 회차 문제를 안전하게 추가할 수 있다.
2. QCODE 중복을 자동 점검한다.
3. 데이터 오류 발생 시 이벤트 로그 기준으로 복구할 수 있다.
4. 운영자가 개발자 도움 없이 기본 데이터 업데이트를 수행할 수 있다.

## 11. V3.0 1차 고도화 범위

GEP V2.0이 이미 작동 앱이므로, V3.0의 첫 번째 범위는 신규 MVP가 아니라 V2.0 기능을 안정화하고 표준화하는 1차 고도화로 정의한다.

1차 고도화는 다음 기능을 기준으로 한다.

1. 사용자 등록
2. 전화번호 기반 재접속
3. 회차별 문제풀이
4. 과목별 문제풀이
5. 정답 확인
6. 이어풀기
7. 일일 통계
8. 누적 통계
9. 과목별 정답률
10. OX 진위형 학습
11. 회차별 모의고사
12. 맞춤 모의고사

1차 고도화에서 후순위로 두는 기능은 다음과 같다.

1. 결제
2. AI 추천
3. 자동 개입 시스템
4. 고급 차트
5. 다중 디바이스 실시간 동기화
6. 복잡한 캐시 및 성능 최적화

## 12. 성공 기준

V3.0은 다음 기준을 충족할 때 1차 성공으로 판단한다.

1. 20회부터 30회까지의 기출문제를 안정적으로 조회할 수 있다.
2. 사용자가 회차별, 과목별 문제를 풀 수 있다.
3. 사용자의 답안 이벤트가 누락 없이 기록된다.
4. 이어풀기 지점이 정확하게 유지된다.
5. 일일, 누적, 과목별 통계가 정확하게 계산된다.
6. 데이터 마스터의 QUESTION 필드가 훼손되지 않는다.
7. 신규 회차 추가 절차가 문서화된다.
8. 핵심 파일 구조가 단순하게 유지된다.

## 13. 주요 리스크와 대응

### 13.1 데이터 품질 리스크

리스크: PDF 변환 과정에서 문제, 보기, 정답, 과목 분류 오류가 발생할 수 있다.

대응:

1. 엑셀 마스터에서 운영자 검증 후 JSON 변환
2. QCODE 중복 검사
3. 필수 필드 누락 검사
4. 정답 값 범위 검사

### 13.2 통계 불일치 리스크

리스크: 진행 데이터, 통계 데이터, 이벤트 로그가 서로 다를 수 있다.

대응:

1. 이벤트 로그를 최종 기준으로 삼는다.
2. 통계와 진행 데이터는 재계산 가능한 파생 데이터로 둔다.
3. `rebuild_statistics.py` 도구를 만든다.

### 13.3 구조 복잡화 리스크

리스크: 기능 추가 과정에서 파일과 클래스가 과도하게 늘어날 수 있다.

대응:

1. MVP 단계에서는 핵심 파일만 유지한다.
2. 사용자 가치가 명확하지 않은 모듈은 만들지 않는다.
3. 공통 로직은 단위 함수로 먼저 작성한다.
4. 클래스는 상태와 책임이 분명할 때만 사용한다.

### 13.4 서비스 범위 확장 리스크

리스크: 고급 기능을 너무 빨리 넣으면 MVP 검증이 늦어진다.

대응:

1. Phase 1과 Phase 2 완료 전 고급 기능 구현을 시작하지 않는다.
2. 결제, AI 추천, 자동화 개입은 MVP 이후로 둔다.
3. 실제 사용자 학습 흐름 검증을 우선한다.

## 14. 즉시 실행 과제

1. 마스터 엑셀 후보 파일 확정
2. 데이터 필드 표준 확정
3. `questions_master.json` 생성 계획 수립
4. MVP 화면 와이어프레임 확정
5. Flask 기반 단순 앱 구조 생성
6. 사용자 등록 및 문제풀이 API부터 구현

## 15. 결론

GEPv3.0의 핵심은 새로운 기능을 많이 추가하는 것이 아니라, 보험중개사 시험 수험생이 매일 반복해서 사용할 수 있는 안정적인 학습 서비스를 완성하는 것이다.

V3.0은 V2.0의 기능 경험과 문서 자산을 계승하되, 구조는 더 단순하게 가져간다. 먼저 MVP를 빠르게 완성하고, 이후 틀린문제, 미니모의고사, 고급 통계, 결제, AI 추천을 단계적으로 얹는 것이 가장 안전한 개발 전략이다.

최우선 원칙은 다음 한 문장으로 정리한다.

**기출문제 원천 데이터는 보존하고, 사용자 학습 이벤트는 빠짐없이 기록하며, 서비스 구조는 단순하게 유지한다.**
